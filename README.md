# 招聘全流程AI助手

一个陪伴 HR 走完招聘全流程的 AI 智能体：从发布岗位、设计面试，到简历筛查、面试衔接，再到最终的录用对比。

- **在线体验**：<https://code.coze.cn/web-sdk/7696319428673437737>（需登录扣子账号）
- **搭建平台**：扣子编程（Coze）
- **作者**：申竹妍（HRBP 方向，2027 届）

---

## 为什么做这个

在 HR 实习中，我反复遇到这几个问题：

- 业务方的用人需求很模糊，JD 要来回改好几轮；
- 面试题临时准备，不同面试官问的问题、打分标准都不一样；
- 线上面试时，越来越难判断候选人是不是在借助 AI 作答；
- 多轮面试之间信息断层，二面面试官不知道一面留下了哪些疑点；
- 最后比较候选人时，常常凭整体印象拍板。

这个助手把我在实习中沉淀的招聘方法，固化成一套可复用的流程。

## 四项功能

| 功能 | 输入 | 输出 |
|---|---|---|
| 一、生成招聘工具包 | 岗位信息、面试轮次、招聘政策 | JD、分轮次结构化面试题、AI 防作弊设计、评委打分细则 |
| 二、简历门槛筛查 | 岗位任职要求、候选人简历 | 逐条对照的匹配明细、匹配概况、待核实点、按规则给出的建议 |
| 三、面试轮次衔接 | 上一轮面试官反馈 | 待验证清单、下一轮新增追问、考察重点调整 |
| 四、候选人横向对比 | 各候选人各维度得分与权重 | 加权总分对比表、排序与录用建议、分差很小时的关键差异分析 |

在同一次对话中，后面的功能会自动沿用前面生成的岗位信息和打分维度，四个功能可以串成一条完整的招聘流程。

## 设计要点

**1. 面试题按轮次分配，同一能力只考一次**
前面的轮次看基础匹配、动机和沟通，后面的轮次看专业深度和综合判断。打分表里每个能力维度只对应一个考察轮次，和面试题实际所在的轮次保持一致。

**2. 非常规题考察临场思考**
除了行为面试题和情境题，每套题还有 3 道非常规题：估算题、两难取舍题、条件突变题、反向视角题。估算题必须是没有给全数据、需要候选人自己提出假设的题目。

**3. AI 防作弊：信号只用于追问，不用于淘汰**
为每道行为面试题设计 3 层追问，聚焦 AI 难以编造的个人细节，比如具体数字、个人角色、失败经历、前后一致性。但可疑信号只用来决定"需要继续追问"，不能单独作为判定作弊或淘汰的依据，避免误伤紧张的候选人。

**4. 简历筛查用门槛制，不凭印象打分**
必备条件逐条判断是否满足，加分项只在同等条件下作为排序参考。只有"熟练""精通"这类自我描述、没有具体事例的，最高只能评"中"，并列入待核实点。

**5. 招聘合规**
- JD 的必备条件只能来自用户提供的要求，不能自行增加专业、经验等门槛；
- 不在 JD、面试题和评估中出现性别、年龄、婚育状况、地域、外貌等歧视性内容；
- 提醒用户在粘贴简历前删去姓名、电话、证件号等个人信息；
- 所有评估结论只作参考，最终录用决定由招聘团队做出。

## 迭代记录

这个助手经过了多轮测试与修改，以下是主要的问题和解决方法：

| 测试中发现的问题 | 原因分析 | 解决方法 |
|---|---|---|
| JD 自行增加了"人力资源管理相关专业"这一必备条件 | 模型会根据经验"补全"要求 | 规定必备条件只能来自用户输入，补充内容只能放进加分项 |
| 横向对比的加权总分算错（应为 3.85，输出 4.05） | 大模型做算术本质上是在预测数字，容易出错 | 新增 Python 计算工具 `calculate_weighted_scores`，加权分由程序计算 |
| 简历匹配度总是凭印象给出 92 分，不调用计算工具 | 模型把"匹配度评估"理解为写报告，不认为需要计算 | 改为门槛制，去掉总分，从根源上避开算术 |
| 修改配置后，测试窗口的输出没有变化 | 预览环境没有加载最新配置 | 对比部署版与预览版的输出，确认部署版按新规则运行 |
| 打分表的"考察轮次"和面试题实际所在的轮次对不上 | 规则没有要求两者一致 | 规定每个维度只填一个轮次，并且必须与题目所在轮次一致 |

**已知问题**：简历筛查中，偶尔会出现某项能力评为"高"、同时又被列入待核实点的情况，与规则不完全一致，后续计划继续优化。
